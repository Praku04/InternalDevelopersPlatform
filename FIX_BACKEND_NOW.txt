The backend container is missing. Let's check logs and fix it.

-------------------------------------------------------------------
STEP 1: Check What Happened
-------------------------------------------------------------------

Run this to see backend logs (if container ever started):

docker-compose logs backend --tail 50

-------------------------------------------------------------------
STEP 2: Quick Fix - Option A (Automated)
-------------------------------------------------------------------

chmod +x fix-backend.sh && ./fix-backend.sh

-------------------------------------------------------------------
STEP 2: Quick Fix - Option B (Manual)
-------------------------------------------------------------------

If the script doesn't work, run these commands:

# Stop everything
docker-compose down

# Remove backend container and image
docker rm -f internaldevelopersplatform-backend-1
docker rmi internaldevelopersplatform-backend

# Rebuild backend
docker-compose build --no-cache backend

# Start everything
docker-compose up -d

# Wait and check
sleep 10
docker-compose ps

-------------------------------------------------------------------
STEP 3: Check Backend Logs
-------------------------------------------------------------------

docker logs internaldevelopersplatform-backend-1

# Look for errors in the output

-------------------------------------------------------------------
STEP 4: Test Backend
-------------------------------------------------------------------

curl http://localhost:8100/api/v1/health

# Should return: {"status":"healthy"}

-------------------------------------------------------------------
COMMON ISSUES & SOLUTIONS
-------------------------------------------------------------------

Issue 1: "Port 8100 already in use"
Solution:
  sudo lsof -i :8100
  sudo kill -9 <PID>
  docker-compose up -d backend

Issue 2: "Python module not found"
Solution:
  docker-compose build --no-cache backend
  docker-compose up -d backend

Issue 3: "Cannot connect to dynamodb"
Solution:
  docker-compose restart dynamodb-local
  docker-compose restart backend

Issue 4: Container keeps restarting
Solution:
  docker logs internaldevelopersplatform-backend-1 --follow
  # Watch for errors

-------------------------------------------------------------------
COMPLETE CLEAN RESTART
-------------------------------------------------------------------

If nothing works, do a complete clean restart:

# Stop everything
docker-compose down

# Clean Docker
docker system prune -f

# Remove all project containers
docker rm -f $(docker ps -a | grep internaldevelopers | awk '{print $1}')

# Remove all project images
docker rmi -f $(docker images | grep internaldevelopers | awk '{print $3}')

# Rebuild everything
docker-compose build --no-cache

# Start everything
docker-compose up -d

# Check status
docker-compose ps

# Check logs

-------------------------------------------------------------------
WHAT TO CHECK IN LOGS
-------------------------------------------------------------------

Good logs look like:
  INFO:     Started server process
  INFO:     Waiting for application startup.
  INFO:     Application startup complete.
  INFO:     Uvicorn running on http://0.0.0.0:8000

Bad logs show:
  ModuleNotFoundError: No module named 'X'
  Address already in use
  Connection refused
  FATAL ERROR
