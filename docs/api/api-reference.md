# API Reference (Phase 1)

Base URL: `http://localhost:8000` (local dev)

## Health

`GET /healthz` → `{"status": "ok"}`

## Modules

`GET /api/v1/modules` — list all modules in the registry
`GET /api/v1/modules/{module_name}` — get one module, 404 if not found
`POST /api/v1/modules/search` — body `{"capabilities": ["encrypted-ebs", ...]}`,
returns approved modules whose capability set is a superset of the request

## Requests

`POST /api/v1/requests` — body: a `DeploymentSpecification` (see
`ai/schemas/deployment_specification.schema.json`); 201 on success, 409 if
`request_id` already exists
`GET /api/v1/requests` — list all requests (in-memory, Phase 1 only)
`GET /api/v1/requests/{request_id}` — get one request, 404 if not found
`GET /api/v1/requests/{request_id}/status` — current lifecycle status
(`SUBMITTED`, `TERRAFORM_GENERATED`, `PLAN_PASSED`, `PLAN_FAILED`)

## Terraform

`POST /api/v1/terraform/plan` — body `{"request_id": "..."}`; generates a
Terraform root config from the stored DeploymentSpecification (composing
approved modules only) and runs `fmt`/`init`/`validate`/`plan` through the
whitelisted engine. Returns a step-by-step result; 404 if the request
doesn't exist. `apply`/`destroy` are not exposed by this or any endpoint —
`TerraformEngine` has no such methods.
`GET /api/v1/terraform/plan/{request_id}` — most recent plan result for a
request, 404 if none has been run yet

Full interactive docs are auto-generated by FastAPI at `/docs` when the
backend is running.

Everything else in Section 32 of the original build prompt (`/api/v1/ai/*`,
`/api/v1/terraform/*`, `/api/v1/security/*`, `/api/v1/approvals/*`,
`/api/v1/deployments/*`, `/api/v1/inventory/*`, `/api/v1/dashboard/*`,
`/api/v1/audit`) is planned for later phases and not yet implemented.
Authentication/authorization is also not yet implemented — all Phase 1
endpoints are currently unauthenticated for local development only.
